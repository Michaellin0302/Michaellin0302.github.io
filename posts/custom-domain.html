绑上自己的域名:blog.midodo.tech

2026-11-21|Michaellin0302|约 4 分钟|系列:建站记 · 第 5 篇

michaellin0302.github.io 虽然免费,但又长又难记。这篇记录我怎么把已有域名 midodo.tech 绑到博客上——过程比预想的曲折,还挖出 GitHub 一个深坑,但 DNS 始终只需要一条命令。

主域名 vs 子域名:解析方式不一样

绑域名之前要先搞清两种情况:

  • 子域名(如 blog.midodo.tech):加一条 CNAME 记录指向 用户名.github.io 即可,最简单
  • 主域名(如 midodo.tech):不能用 CNAME(DNS 规范限制),要加 4 条 A 记录指向 GitHub Pages 的固定 IP:185.199.108.153、185.199.109.153、185.199.110.153、185.199.111.153
💡我选了子域名方案:一条记录搞定,主域名的其他解析(邮箱等)完全不受影响。

用阿里云 CLI 加解析:一条命令

域名在阿里云,装好 aliyun 命令行工具并配置好凭证后,加一条解析就是一行命令:

aliyun alidns AddDomainRecord \
  --DomainName midodo.tech \
  --RR my \
  --Type CNAME \
  --Value michaellin0302.github.io \
  --TTL 600

返回一个 RecordId 就成功了。用 nslookup blog.midodo.tech 验证,能解析到 GitHub 的 IP 就说明 DNS 生效。

GitHub 侧两步

  1. 仓库根目录加一个 CNAME 文件,内容一行:blog.midodo.tech
  2. 仓库 Settings → Pages 里填上自定义域名(或者用 API:PUT /repos/用户名/仓库/pages)

之后 GitHub 会自动做两件事:把 github.io 地址 301 重定向到新域名;为你的域名自动签发 Let's Encrypt HTTPS 证书。

真正的坑:域名被卡死怎么办

DNS 十分钟就生效了,但 my 的 HTTPS 证书等了两个多小时还没签下来:证书透明度日志(crt.sh)里查无此证,境外访问 TLS 握手直接被重置,GitHub 配置里的 https_enforced 也迟迟不翻转——这不是"慢",是签发流水线被反复改配置卡死了。

解法出乎意料地简单:换一个全新的子域名。加一条 blog 的 CNAME,把仓库 CNAME 文件和 Pages 设置都改成它——十分钟后证书签发成功,全球多地拨测全部 200。管线本身没问题,只是 my 这个名字在 GitHub 侧留下了僵死状态。

💡教训:绑定域名尽量一次到位,别反复增删;如果证书超过一小时不签发,别死等,换个子域名立刻解决。

成本结算

  • 域名:.tech 属于便宜档,一年几十元(买域名需实名认证)
  • 解析:阿里云免费 DNS 即可
  • 托管 + 证书:GitHub Pages 白送

输入 blog.midodo.tech 看到自己的博客的那一刻,成就感拉满。
