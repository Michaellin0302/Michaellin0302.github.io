国内访问 GitHub 的坑与填坑工具

2026-11-21|Michaellin0302|约 5 分钟|系列:建站记 · 第 4 篇

这篇完全是我今天下午的实战记录:git push 连续三次 Connection was reset,最后靠一套组合拳救场。以下是踩坑后的完整总结。

先说现象

国内访问 GitHub 的典型症状:

  • 网页打开慢,头像、图片加载不出来
  • git clone 大仓库到一半断开
  • git push 报 Recv failure: Connection was reset 或直接连不上 443 端口

根源通常不是本地带宽,而是 DNS 污染 + 国际链路抖动,而且它是间歇性的:几分钟前还通畅,转眼就全断。我今天就遇到了——网页能开,API 能用,唯独 git push 走不通。

工具箱(从简单到进阶)

1. Watt Toolkit(原 Steam++)—— 最省事

免费开源工具,勾选 GitHub 一键加速,新手推荐。

2. 修改 Hosts —— 改善网页加载

用 GitHub520 这类自动更新 IP 的项目,绕过 DNS 污染。

3. 加速代理 —— 下载文件提速

下载 Release 文件时,在 URL 前面套一层 ghfast、gh-proxy 这类加速前缀,速度能翻好几倍。

4. Gitee 中转 —— 日常开发最稳

把仓库导入 Gitee,本地配置两个 remote,日常 push 走 Gitee(国内飞快),定期同步回 GitHub。

进阶:SSH over 443

今天诊断时发现一个规律:HTTPS 到 github.com 被重置,但 ssh.github.com:443 是通的——因为它跑的是 SSH 协议,识别难度不同。启用方法:

# 把远程地址换成 SSH over 443 通道
git remote set-url origin ssh://git@ssh.github.com:443/用户名/仓库名.git

前提是先在 GitHub 账号里绑定 SSH 公钥(ssh-keygen 生成,粘贴到 Settings → SSH keys)。

终极兜底:GitHub API 直接写提交

最意外的一招:HTTPS 和 SSH 都堵死的时候,api.github.com 有时仍然可用。通过 Git Data API 也能完成一次完整的提交:

  1. POST /git/blobs 上传文件内容 → 得到 blob sha
  2. POST /git/trees 建目录树
  3. POST /git/commits 创建提交
  4. PATCH /git/refs/heads/main 移动分支指针
💡这正是我今天救场用的方法。教训是:此路不通,换条路走——工具链的每一层都值得了解一层原理。

我的最终组合

  • 日常浏览:改 hosts + 偶尔开 Watt Toolkit
  • git 推送:优先 HTTPS 直连,失败切 SSH over 443,再不行走 API 兜底
  • 大文件下载:加速代理前缀

网络是间歇抽风,但工具箱是永久积累的。
